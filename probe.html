probe

Find out what this machine can build and run: a native window, a Python py2app can use, a server that has started, a copy of the app that is running

Before kavacha builds an app or opens a window, it needs a few facts about the machine it is on: whether a native window can be opened, which installed Python py2app can build with, whether the app’s local server has started, and whether a copy of the app is already running. This module finds them out. None of its functions raise when the answer is no. They return None, False or an empty list instead, so a caller can print a clear message.

pywebview is the library that draws the native window. It uses a different web engine on each platform and calls each one a GUI: cocoa on macOS, edgechromium (Microsoft Edge WebView2) on Windows and gtk on Linux. BACKENDS maps Python’s sys.platform names to these. FRAMEWORK_CANDIDATES is used by framework_python, further down.

backend looks up the GUI for a platform, the current one by default, and returns None for a platform pywebview does not support. shell_ready checks the two things a window needs, a supported platform and an installed pywebview, and returns (True, gui) or (False, reason). Call it before opening a window, so that a missing dependency produces a readable message instead of an import error.

py_version

def py_version(
    python
):

The (major, minor) of python, or None when it will not say.

py2app copies the Python interpreter into the bundle, and it can only do that with a framework build. A framework build is the macOS layout that python.org, Homebrew and Apple’s command line tools install, with the interpreter inside a Python.framework folder. The interpreters uv and pyenv download are python-build-standalone builds, which are laid out differently and cannot be embedded.

is_framework checks one interpreter by running it and asking. With no argument it checks the Python running kavacha. When it checks another interpreter, it also requires Python 3.12 or later. py_version asks an interpreter for its (major, minor) version. framework_python goes through FRAMEWORK_CANDIDATES, the usual install paths, and returns the first framework build it finds, or None. All three treat an interpreter that is missing or will not run as a no, without raising.

The example uses three stand-in interpreters, small shell scripts that answer the probe the way a real one would. The first is a framework build of 3.13, which py2app can use. The second is a framework build of 3.11, which is too old. The third is a standalone 3.13, whose PYTHONFRAMEWORK setting is empty, as it is for every interpreter uv and pyenv install.

is_framework(fw), is_framework(old), is_framework(pbs)
(True, False, False)

wait_for_http

def wait_for_http(
    url, timeout:int=60, interval:float=0.1
):

Wait until url answers with a success status or timeout seconds pass, and return whether it did.

An app’s window should not load its page until the local server is listening, or the user sees a connection error. wait_for_http requests url every interval seconds until a request succeeds or timeout seconds pass, and returns True or False. Here the server has to answer with a success status, so a 404 counts as not ready. kavacha.window has its own wait_for_http, which accepts any HTTP response.

test_eq(wait_for_http(url), True)
test_eq(wait_for_http(url + 'missing', timeout=.3, interval=.05), False)

running_from

def running_from(
    bundle, ps_output:NoneType=None
):

PIDs of processes whose executable is inside bundle.

Rebuilding an app while a copy of it is running breaks the running copy, because the build replaces files it is still reading. running_from lists the process IDs of programs whose executable is inside the folder bundle. It reads the output of ps, or the text you pass as ps_output, which is how the example runs without a real app. Only the executable path counts, so a grep that mentions the bundle, or an app in a folder with a similar name, does not match. The current process is never listed, and if ps cannot run the result is an empty list.

ps = """  PID COMMAND
  101 /Apps/Demo.app/Contents/MacOS/Demo --serve
  102 /usr/bin/grep -r /Apps/Demo.app
  103 /Apps/Demo.app.old/Contents/MacOS/Demo
  104 /bin/zsh
"""
running_from('/Apps/Demo.app', ps)
[101]
