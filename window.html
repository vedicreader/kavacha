window

Open a native window on a local web app, with the menu bar, Dock menu and quit behaviour of a desktop app

This module is the part of kavacha that runs inside the finished app. It opens a native window that shows a web app served from a loopback address, one on the same machine such as 127.0.0.1, and gives that window what people expect of a desktop app: a menu bar, a Dock menu of recent folders, a window that hides instead of quitting when it is closed, and a response when a folder is dropped on the app’s icon. pywebview draws the window, and most of the platform-specific parts are for macOS.

The application that uses kavacha is called the host here. It supplies its name, its menus and the callbacks that do its own work, such as opening a folder. run_shell, near the end, is the function a host calls. Everything above it is a piece run_shell is built from.

use_app

def use_app(
    name, cfg:NoneType=None, env_prefix:str='KAVACHA_'
):

Set the app name, the config and storage folders, and the environment variable prefix kavacha uses.

A few things are named after the app: the folder where the window keeps its settings and browser storage, the title on the holding page, and the prefix of the environment variables kavacha reads. APP_NAME is that name. It is read from $KAVACHA_APP_NAME when the module is imported and defaults to app. CFG is the settings folder, from $KAVACHA_CFG or else the XDG config folder named after the app, such as ~/.config/app.

A host should call use_app once, before it opens a window, with its own name. It sets APP_NAME, CFG, STORAGE and the environment variable prefix together. After use_app('leela', env_prefix='LEELA_'), for example, the window size comes from $LEELA_WINDOW_SIZE instead of $KAVACHA_WINDOW_SIZE, and the settings folder from $LEELA_CFG. None of this creates anything on disk.

ShellApi

def ShellApi(
    *args, **kwargs
):

What the page may ask the native window for, as window.pywebview.api.*.

The page in the window sometimes needs the operating system, for example to show the native folder chooser. pywebview allows this through a JavaScript API: the methods of a Python object become functions the page calls as window.pywebview.api.<method>(). ShellApi is that object.

pick_folder shows the platform’s folder chooser and returns the chosen path, or None if the user cancels. pick_path does the same with a chooser that takes a file or a folder, as File > Open does in a Mac app. open_folder and recent pass the request to the host’s on_open_folder and on_recent callbacks, which run_shell sets. Without a callback, open_folder returns False and recent returns an empty list. open_path takes either kind: a folder goes the way of open_folder, and a file goes to on_open_file, the callback a file opened from Finder reaches. A host that must tell a request from the page apart from a Finder or Dock open sets on_page_folder: open_folder then calls it in place of on_open_folder. on_picked gets each folder the person chooses in pick_folder or pick_path, before the page sees it, so the host can trust that one path. It is not called for a file or when the person cancels. pywebview calls these methods on its own worker threads, so the callbacks must be safe to call from any thread. dropped is for files dropped on the window, described with arm_drops below. The page cannot call the on_ callbacks themselves: pywebview offers the page every function an object lists, so ShellApi lists none of them.

set_background is for a page with themes. It takes the page’s background as #rrggbb and paints every open window’s native background with it, which is what shows while the window opens or grows faster than the page redraws. It also keeps the colour in background, so a window opened later starts on it. The colour is per app, not per window: pywebview does not say which window called. Anything that is not #rrggbb returns False and changes nothing.

api = ShellApi()
opened = []
api.on_open_folder = opened.append
api.open_folder('/proj/demo'), api.open_folder(''), opened
(True, False, ['/proj/demo'])

A page request goes to on_page_folder when the host sets it. Finder and the Dock still use on_open_folder.

two, page = ShellApi(), []
two.on_open_folder, two.on_page_folder = opened.append, page.append
two.open_folder('/proj/two')
test_eq(page, ['/proj/two'])
test_eq(opened, ['/proj/demo'])

on_picked gets the folder the person chose, and is not called on a cancel. A fake webview module stands in for the real chooser.

import sys, tempfile, types
from unittest.mock import patch
def fake_webview(answer): return types.SimpleNamespace(FileDialog=types.SimpleNamespace(FOLDER=20), active_window=lambda: types.SimpleNamespace(create_file_dialog=lambda kind: answer))
picked = []
two.on_picked = picked.append
with patch.dict(sys.modules, webview=fake_webview(['/proj/chosen'])): test_eq(two.pick_folder(), '/proj/chosen')
with patch.dict(sys.modules, webview=fake_webview(None)): test_eq(two.pick_folder(), None)
test_eq(picked, ['/proj/chosen'])

warm_cdp

def warm_cdp(
    port:NoneType=None, profile:NoneType=None
):

Start the CDP Chrome at launch, but only when the EAGER_CDP environment variable is 1, true or yes.

Some hosts show web pages inside the app through a separate Chrome that they control over the Chrome DevTools Protocol (CDP), using fossick. start_cdp starts that Chrome on port in a background thread and returns the thread. If a Chrome is already listening on port, it does nothing. If fossick is not installed or Chrome fails to start, it prints a message and the app carries on without it. Pass wait=True to wait for the start, for up to timeout seconds or 30 by default. profile is the Chrome user data folder.

cdp_target picks the port and the profile. A visible Chrome uses port, or CDP_PORT (9223), and profile, or fastcdp’s own profile. A headless Chrome uses HEADLESS_PORT (9224) and HEADLESS_PROFILE. It never uses port 9223 or fastcdp’s profile, because those belong to the visible CDP Chrome. A headless Chrome on that port and profile takes over the visible Chrome: a click on its app then opens nothing. fossick starts Chrome through fastcdp’s chrome_bin, so the FASTCDP_CHROME environment variable chooses the browser.

Starting Chrome takes time and memory, so a host normally starts it the first time it is needed. warm_cdp starts it at launch instead, but only when the environment variable named in EAGER_CDP, KAVACHA_CDP_EAGER unless use_app changed the prefix, is 1, true or yes in lower case. Otherwise it returns None.

dock_delegates

def dock_delegates():

The two delegate subclasses. Built once: an Objective-C class name is global to the runtime.

Most macOS apps keep running when their last window is closed, and clicking the Dock icon brings the window back. kavacha does the same. Closing a window hides it, and clicking the Dock icon shows the window that was hidden most recently. Quitting with Cmd+Q still ends the app, after running quit_cleanly. This works by replacing pywebview’s window and app delegates, the objects AppKit asks how to respond to events such as a window closing; dock_delegates builds the two replacement classes once, and keep_running_in_dock, below, installs them. The hidden windows wait in hidden_windows, the most recently hidden last.

quit_cleanly

def quit_cleanly(
    timeout:int=15, run_exit:NoneType=None, grace:float=1.0
):

Stop this process’s multiprocessing children, then run its atexit handlers, which a Cocoa quit’s C exit() skips.

When a Cocoa app quits, it ends the process with C’s exit(), which skips Python’s atexit handlers, and worker processes can outlive it. A worker pool started by forking, as fastcore.parallel does on macOS, keeps pipes open that hold its children alive. quit_cleanly terminates each child process of this one, kills any still running after one shared grace of a second, then runs the atexit handlers on a thread and waits at most timeout seconds for them. It reaps once more afterwards, for a pool a still-running thread started meanwhile, and returns the number of children it stopped. It sets quitting first, so a host’s background job can tell being reaped from failing. run_exit replaces the atexit handlers, which is how the test below checks it without exiting.

quit_on_sigterm makes a SIGTERM, the signal kill sends by default, quit the app the way Cmd+Q does, so that the same clean-up runs. It works on macOS only, must be called on the main thread, and is called by run_shell. A forked child gets the default SIGTERM back and lets go of the wakeup socket, and a multiprocessing child exits once its parent is gone, so a Force Quit or a crash leaves no idle worker behind. Once a quit begins, a second SIGTERM kills.

import multiprocessing as mp, subprocess, tempfile
kid = mp.get_context('fork').Process(target=time.sleep, args=(60,)); kid.start()
ran = []
test_eq(quit_cleanly(run_exit=lambda: ran.append(1)), 1)
test_eq((kid.is_alive(), ran), (False, [1]))
t0 = time.time(); quit_cleanly(timeout=.3, run_exit=lambda: time.sleep(30))
assert time.time() - t0 < 5, 'a hung handler does not hold the quit'
_fork_probe = r'''
import os, signal, sys, time, multiprocessing as mp
from concurrent.futures import ProcessPoolExecutor
from kavacha.window import quit_on_sigterm, quit_cleanly
def ignore(): signal.signal(signal.SIGTERM, signal.SIG_IGN); time.sleep(60)
def nested(path):
    ex = ProcessPoolExecutor(2, mp_context=mp.get_context('fork')); list(ex.map(abs, range(4)))
    open(path, 'w').write(' '.join(str(p.pid) for p in mp.active_children())); time.sleep(60)
def alive(pid):
    try: os.kill(pid, 0); return True
    except OSError: return False
if __name__ == '__main__':
    r, w = quit_on_sigterm(); r.setblocking(False)
    fork = mp.get_context('fork')
    kid = fork.Process(target=time.sleep, args=(60,)); kid.start(); time.sleep(.3)
    kid.terminate(); kid.join(5)
    assert kid.exitcode == -signal.SIGTERM, kid.exitcode
    try: assert not r.recv(64), "a child's SIGTERM reached the parent's wakeup socket"
    except BlockingIOError: pass
    ex = ProcessPoolExecutor(4, mp_context=fork); list(ex.map(abs, range(8)))
    pool = [p.pid for p in mp.active_children()]
    stubborn = [fork.Process(target=ignore) for _ in range(4)]
    for p in stubborn: p.start()
    time.sleep(.5); t0 = time.time()
    assert quit_cleanly(run_exit=lambda: None, grace=.5) == 8
    assert time.time() - t0 < 4, f'{time.time()-t0:.1f}s: one shared grace, not one per child'
    assert not [p for p in pool if alive(p)], 'pool workers outlived quit_cleanly'
    assert signal.getsignal(signal.SIGTERM) == signal.SIG_DFL, 'a second SIGTERM must kill a hung quit'
    mid = fork.Process(target=nested, args=(sys.argv[1],)); mid.start()
    while not os.path.exists(sys.argv[1]) or not open(sys.argv[1]).read(): time.sleep(.1)
    grand = [int(x) for x in open(sys.argv[1]).read().split()]
    os.kill(mid.pid, signal.SIGKILL); mid.join()
    end = time.time() + 5
    while [g for g in grand if alive(g)] and time.time() < end: time.sleep(.2)
    assert not [g for g in grand if alive(g)], 'workers outlived a parent that was SIGKILLed'
    print('ok')
'''
if sys.platform == 'darwin':
    with tempfile.TemporaryDirectory() as d:
        r = subprocess.run([sys.executable, '-c', _fork_probe, f'{d}/grand'], capture_output=True, text=True, timeout=120)
    assert r.stdout.strip() == 'ok', r.stdout + r.stderr

make_window

def make_window(
    title:NoneType=None, size:NoneType=None, background:NoneType=None
):

A window on the splash, waiting for a URL, on window_background(background).

make_window creates a window showing the splash page, titled title (the app’s name by default) and sized size (from window_size by default). It does not load a URL; open_window and run_shell do that once the server answers. It also creates the STORAGE folder if needed. The window and its splash take window_background(background), so with no background a window opens on the colour the page last set. On macOS each page the window loads gets arm_drops, so a file dropped on it opens.

A unified title bar

A host whose page draws its own top row can merge that row with the window’s title bar. The host sets shell_api().unified = True before it opens windows, and each platform then does what is native to it:

  • On macOS the page lies under a transparent title bar with no title. An empty unified toolbar makes the bar 52 points high, so the traffic lights sit centred in the page’s top row. The page leaves about 80 pixels free at its left for them. The title is still set, so the Window menu, Mission Control and tools that read the title still have it.
  • On Windows the native caption stays, with its minimise, maximise and close buttons, snap layouts and keyboard behaviour. tint_caption paints it in the page’s background, with dark mode on a dark one, so the caption and the page’s top row read as one bar. Windows 11 takes the caption colours; Windows 10 takes only dark mode.
  • Elsewhere nothing changes.

The page learns the mode two ways: with_titlebar puts it on the first URL as titlebar=<mode>, so the page can lay out its first paint, and ShellApi.titlebar answers it once pywebview’s bridge is up. The page marks the row that drags the window with pywebview’s pywebview-drag-region class. WebKit ignores -webkit-app-region, so pywebview’s own drag code moves the window, and only a press on the marked element itself starts a drag.

off_main_thread

def off_main_thread(
    fn, name:str='kavacha-shell'
):

Run fn(arg) on a thread of its own; create_window builds nothing on the main thread.

Native events, such as a click in the Dock menu or a folder dropped on the app’s icon, arrive on the main thread, inside the GUI loop, and pywebview cannot build a window from there. off_main_thread wraps fn so that each call runs on a new daemon thread named name instead. bring_forward

def bring_forward():

Activate the app, and drop the hidden-window entries whose window is on screen again. macOS only.

open_window opens a window on url while the app is running, for example when the user opens another folder. key identifies the window, such as the folder’s path. If a window with that key is already open, open_window shows it, even if it was hidden to the Dock, instead of opening a second one. Either way it activates the app with bring_forward, so a window opened from Finder is not left behind other apps. The windows that have a key are kept in the dictionary keyed_windows, which run_shell also fills. Otherwise it creates a window, shows the splash, waits up to url_wait seconds for the server and loads the page, or shows the unreachable page if the server never answers. It blocks while it waits, so call it from a thread made by off_main_thread.

The example uses stand-in windows. The first is brought to the front. The second fails to come to the front, so open_window prints why and returns it as it is.

unify_nswindow

def unify_nswindow(
    nsw, toolbar:NoneType=None
):

Lay nsw’s content under a transparent title bar with no title, 52 points high so the traffic lights centre in the page’s top row.

unified_titlebar is what make_window runs before a unified window is shown. run_shell

def run_shell(
    urls, titles:tuple=(), url_wait:int=90, gui:NoneType=None, icon:NoneType=None, size:NoneType=None,
    on_ready:NoneType=None, on_open_folder:NoneType=None, keys:tuple=(), bar:tuple=(), lookup:NoneType=None,
    on_action:NoneType=None, on_recent:NoneType=None, background:NoneType=None, on_open_file:NoneType=None
):

Open one native window per workspace URL and block until they close.

run_shell is the entry point. It opens one window per URL in the list urls, titled with the matching entry of titles, and runs the GUI loop until the app quits. Call it on the main thread, after starting the servers on another thread or in another process. Each window shows the splash until its server answers, for up to url_wait seconds. It raises a RuntimeError if no window can be opened here and a ValueError if urls is empty.

The other arguments are optional:

  • size is a (width, height) tuple for every window; without it window_size decides.
  • gui overrides the pywebview GUI that shell_ready picks, and icon is the window icon.
  • on_ready is called once every window has loaded its page.
  • on_open_folder and on_recent are the host’s callbacks for opening a folder and for listing recent ones. They serve ShellApi, the Dock menu and folders dropped on the app’s icon.
  • on_open_file is called with the path of each file the user opens with the app from Finder, by double-click or Open With, whether the app is running or being launched by it.
  • keys gives each window a key, so that open_window can find it later.
  • background is the colour every window opens on, as window_background reads it: a host with themes passes its page background, so the window does not flash another colour before the page paints.
  • bar, lookup and on_action describe the menu bar, as explained below.

On macOS it also turns off text substitution, keeps the app in the Dock when its last window closes, and makes SIGTERM quit cleanly. Setting the environment variable <prefix>WEBVIEW_DEBUG turns on pywebview’s debug mode.

watch_open_events

def watch_open_events(
    on_folder:NoneType=None, on_file:NoneType=None
):

Answer the odoc Apple Event Finder sends a running app. macOS only, best-effort.

When the user drops a folder on the app’s Dock icon, or opens a folder with the app from Finder, macOS sends the running app an “open documents” Apple Event, odoc. watch_open_events registers a handler for it that hands the paths in the event to open_paths, which calls on_folder for each folder and on_file for each file. run_shell registers it with the host’s callbacks, already wrapped by off_main_thread. The app delegate receives the same opens through application:openFiles:, and open_paths keeps a path that arrives both ways from being delivered twice. It returns the handler, or None on other platforms or if registration fails.

AppKit can only call methods on Objective-C objects, so the Dock menu rows and the Apple Event handler each need a small NSObject subclass that passes the call on to a Python function: RecentTarget for a Dock menu row and OpenHandler for the event. Where pyobjc is not installed, both classes are None, and the functions that use them only run on macOS.

A menu bar shows keyboard shortcuts next to its items, and pressing one runs the item even while the web page has focus. kavacha writes a shortcut as a chord, such as mod+s: modifier names joined by +, then a key, where mod means Cmd on a Mac. AppKit wants the same shortcut as a key equivalent, which is a single character, plus a modifier mask, a number with one bit per modifier key. CMD, CTRL, ALT and SHIFT are those bits, defined here so that chords can be parsed and tested on any platform.

mac_key

def mac_key(
    chord
):

(keyEquivalent, modifierMask) for one chord, or None when AppKit cannot spell it.

mac_key converts one chord to a (key, mask) pair. It accepts the modifiers mod, cmd, ctrl, alt, opt and shift, an upper-case letter as shorthand for shift and that letter, and named keys such as up, enter, tab and escape. For a sequence of chords, such as mod+k mod+s, it uses only the first.

AppKit matches a key equivalent against the character the key types, so Shift is written into the key and not into the mask: mod+shift+o is O with Command, and mod+shift+/ is ? with Command, the character Shift gives on a US keyboard. A named key such as an arrow types no character, so it keeps the Shift bit. mac_key returns None for hyper, which a window manager takes, and for a chord AppKit cannot show as a key equivalent, such as one with a function key or an unknown modifier like meta.

menu_chord

def menu_chord(
    action, lookup
):

The AppKit chord for action: its first chord with a modifier, not reserved, from a global binding or the only scope with that chord.

A menu shortcut takes the key press before the web page sees it, so only some of the host’s bindings should become one. The host’s keymap is reached through lookup, a function that takes an action name and returns a Binding from kavacha.menus, or None. menu_chord looks up action and returns the AppKit chord of the binding’s first chord that uses a modifier other than shift and is not in RESERVED, and only when the binding either applies everywhere (its scope is global) or is the only binding of that chord in any scope (shared is false). A bare key such as /, or an editor chord that another pane uses too, stays with the page. A lookup that returns some other object with no shared attribute gets chords for its global bindings only.

menu_bar

def menu_bar(
    bar, lookup, on_action, run:NoneType=None
):

Build pywebview menus from bar, and the row table _decorate uses to add native shortcuts and selectors.

menu_bar turns the host’s menu table into pywebview menus. bar is a list of (title, rows) pairs, one per menu, and each row is one of the classes in kavacha.menus. exact_bar

def exact_bar(
    main
):

A menu bar holding the rows of main, where a row fires only for its own chord.

AppKit lets a row with no Shift take the shifted chord of a key that has no case: a row on ⌥↩︎ also runs for ⌥⇧↩︎, before the row that has ⌥⇧↩︎ gets it. exact_bar moves the rows into a bar that, for a Shift chord on such a key, first runs the row whose chord is exactly the one pressed. Other chords go to AppKit as before. The test builds both rows on a bar and presses each chord.

_decorate walks the native menu bar and finishes each row it has a spec for. A Std row loses its target and gets its AppKit selector, so the action goes to whatever has focus, along with the row’s own chord. An action row gets the chord menu_chord allows, if any. The menu titled Window becomes the app’s Windows menu, where macOS lists the open windows.

The menu bar as data

A launcher that builds its own native menu, in another language, needs the same table with every chord already resolved. menu_json gives it: one {'title', 'items'} per menu, where an item is a separator, an action row, a Std row with its selector, or a Js row with its expression.

On a Mac, a row carries key and mask when it has a chord. The chords come from menu_chord and mac_key, the same as _decorate uses.

Off a Mac (mac=False, for example a GTK launcher on Linux), a row carries chord, the label to show, such as Ctrl+Shift+P. A row has accel, a GTK accelerator, only when the launcher may bind it natively. Those rows are the PC_NATIVE launcher rows (Quit, Close Window and Full Screen) and the actions in native, such as a new window, which the page never needs. Every other chord is a label only, so the key press still reaches the page: Ctrl+C in a terminal is still an interrupt. pc_key gives the Std chords, and pc_menu_chord picks an action’s chord as menu_chord does, but it refuses the chords in pc_reserved. A row that pc_key removes is left out, and so is a separator with nothing to separate. mac=None uses the platform the code runs on.
