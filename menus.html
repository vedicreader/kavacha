menus

The row types a menu bar is described with, and the part of a keymap a menu reads

A host describes its menu bar as data: a list of menus, each with a title and a list of rows. This module defines the row types, and the small part of a keymap a menu needs to read. They are plain dataclasses that do not import pywebview or AppKit, so a host can build and test its menu table on any machine. kavacha.window turns the table into a native menu bar on macOS.

The rows

MenuItem is a row that runs one of the host’s actions, named by action. When the user chooses it, the window calls the host’s on_action with that name. A MenuItem with no action is a separator line, which is why action has a default. kind is either empty or warn. warn marks a row the host may want to draw as destructive, such as one that discards changes; kavacha passes it through without acting on it, and refuses any other value.

source

    action:str='', kind:str=''

One action in a menu. A blank action is a separator.

MenuItem('open_folder'), MenuItem()

Std is a row that AppKit already knows how to handle, such as Cut, Copy, Paste and Select All, so the host does not handle it at all. The row names an AppKit selector, such as cut:. The menu sends that selector along AppKit’s responder chain, the chain of objects that starts at whatever has keyboard focus, and the first one that understands it acts. key and mods give the row’s shortcut directly, because a row like this has no entry in the host’s keymap.

Js is a row that runs a JavaScript expression in the focused window, for small jobs such as reloading the page that need no action of their own.

Key bindings

A menu shows each action’s label and shortcut, and the host keeps both in its keymap. kavacha does not read the keymap itself. The host supplies a lookup function that takes an action name and returns a Binding, or None for an action it does not know. A Binding holds the action’s chords, its label, and its scope, meaning where the binding applies. A global binding becomes a menu shortcut. A binding with another scope becomes one only when shared is false, which the host sets when no other scope binds the same chord. A dict’s get method is the simplest lookup, as in the example.

source

Binding

def Binding(
    keys:tuple=(), label:str='', scope:str='global', shared:bool=False
)->None:

What a menu row reads from the host’s keymap: the chords, the label, where it applies, and whether another scope binds its chord.

keys = {'save': Binding(('mod+s',), 'Save'), 'find': Binding(('mod+f',), scope='editor')}
keys.get('save'), keys.get('nothing')

bound is true when the binding has at least one chord. It is worked out from keys instead of being stored, so an unbound action is just Binding() and the two can never disagree.

Chords a menu must not take

A menu shortcut wins over the web page, so a chord the system or a window manager already uses must never become one. RESERVED lists them in the keymap grammar: Hyper (hyper, Command, Control, Option and Shift together) with the keys AeroSpace takes, AeroSpace’s own Control and Option chords, and the macOS system chords. kavacha.window.menu_chord refuses every one of them, and a host can lint its default keymap against the same set.

The launcher’s own rows are Std rows every Mac app has. LAUNCHER_ROWS lists them with their chords, so a host can check that no chord on its own menu bar lands on one of them. Close Window takes ⇧⌘W, which leaves ⌘W for the host’s Close Tab.

How a chord is written for a person

chord_glyph writes one chord the way a Mac menu does: the modifier glyphs in the order ⌃⌥⇧⌘, then the key as a capital letter or a symbol such as ↩︎ or ⌫. With mac=False it writes Ctrl+Shift+P. mod is Command on a Mac and Control elsewhere, hyper is all four modifiers, and a capital letter means Shift. A sequence of chords separated by spaces keeps its spaces. Every place a host shows a chord, such as its menus, palette, help and toasts, can use this one function, so they all agree.

Keys off a Mac

On Linux and Windows, mod is Control. Most chords keep their meaning, but some do not. ⌃⌘F, the Mac chord for Full Screen, becomes Ctrl+F, which is Find. Hide and Minimize have no use under a tiling window manager such as Regolith’s i3 or sway. pc_key gives the chord a Std row takes off a Mac. A Mac-only row takes the chord from a small table: Full Screen is F11, Close Window is Ctrl+Shift+W and Quit is Ctrl+Q. Hide, Hide Others, Minimize, Zoom and Bring All to Front get None, which means that the row is not shown. Every other row keeps its chord, with mod as Control. pc_chord writes any chord in this PC form.

LINUX_RESERVED lists the chords a Linux desktop keeps for itself: Regolith’s and GNOME’s. pc_reserved also refuses every chord with Super, because Regolith owns almost all of them. A host can lint its PC keymap against the same set.

gtk_accel writes a chord as a GTK accelerator, such as <Control><Shift>w. GTK runs a window’s accelerators before the widget that has focus. A native accelerator on Copy would take Ctrl+C away from a terminal in the page, so menu_json gives one only to rows the page never needs. PC_NATIVE names those launcher rows: Quit, Close Window and Full Screen.
