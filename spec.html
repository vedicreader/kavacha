spec

Describe an app once, and get the options py2app or py2exe needs to freeze it

A freezer needs to be told what goes into an app: the script to run, the packages to copy, the modules it would miss, the data files, the icon, and the metadata macOS reads from the bundle’s Info.plist. py2app and py2exe each take this as a dictionary of options, and they name the options differently. This module lets you write the description once, as an App, and produces either dictionary from it.

tree

def tree(
    src, dest, skip:tuple=()
):

List every file under src as the (dest_dir, [files]) pairs a freezer takes, with src mapped to dest.

Data files are files the app reads at run time that are not Python code, such as CSS, JavaScript and images. A freezer takes them as a list of (dest_dir, [files]) pairs, where dest_dir is a folder inside the bundle and files are paths on your disk. tree builds that list for a whole folder. It walks src, mirrors its layout under dest, skips hidden files, __pycache__ and any folder named in skip, and sorts the pairs so that two builds produce the same list. Pass the result as App(data=...). The example skips node_modules and the hidden .DS_Store.

data = tree(src, 'demo/static', skip=['node_modules'])
[(dest, [Path(f).name for f in files]) for dest, files in data]
[('demo/static', ['app.css']),
 ('demo/static/img', ['logo.png']),
 ('demo/static/js', ['app.js'])]

Some packages ship parts compiled with mypyc, and the compiled parts load a helper extension module whose file name contains __mypyc. Nothing imports that helper by name, so a freezer that follows import statements leaves it out and the app fails when it starts. mypyc_modules lists these helpers in the site-packages of the environment you build from, or in the folder site. Add the result to App(includes=...). The helpers’ file names include the Python version and platform, which is why they are looked up at build time instead of written into the spec by hand.

site = Path(tmp.name)/'site'; site.mkdir()
for f in ('chardet__mypyc.cpython-313-darwin.so', 'numpy.cpython-313-darwin.so'): (site/f).write_text('')
mypyc_modules(site)
['chardet__mypyc']

A freezer also pulls in modules no app needs, because something in the environment mentions them. DEFAULT_EXCLUDES lists the usual ones: build tools such as setuptools and the freezers themselves, the standard library’s test suite, other GUI toolkits, and matplotlib. GUI_MODULE names pywebview’s module for each platform, so that a build can leave out the two it does not use.

def App(
    name:str, entry:str, version:str='0.0.0', build:str='', icon:str='', modern_icon:str='', identifier:str='',
    summary:str='', packages:list=<factory>, includes:list=<factory>, excludes:list=<factory>,
    grafted:list=<factory>, unreachable:list=<factory>, data:list=<factory>, plist:dict=<factory>,
    doc_types:list=<factory>, extras:list=<factory>, min_macos:str='11.0',
    category:str='public.app-category.developer-tools'
)->None:

Describe an app once, for whichever freezer this platform uses.

App is the description itself. Only name and entry, the script the app runs, are required; the comment beside each field says what it holds. If you leave out identifier, the reverse-DNS name macOS uses to tell apps apart, it becomes org.<name>.<name> in lower case. bundle_name is the name the freezer gives its output, Demo.app on macOS and Demo elsewhere, and out(root) is where that ends up, under root/dist. The saved output below came from a machine that is not a Mac, so it shows Demo.

app = App(name='Demo', entry='demo_app.py', version='1.2.3', summary='the demo app',
          icon='assets/Demo.icns', packages=['demo', 'fasthtml', 'uvicorn'],
          includes=['demo.cli'], data=data, extras=['desktop'])

CFBundleVersion is what Launch Services compares when several copies of one app are registered, so local builds that all carry the same version leave it picking an arbitrary copy. Setting App.build to a value that grows with every build, such as 1.2.3.29600000, makes the newest copy win. CFBundleShortVersionString stays the version, and with no build both entries are the version.

test_eq(App('Demo', 'd.py', version='1.2.3').info_plist()['CFBundleVersion'], '1.2.3')
built = App('Demo', 'd.py', version='1.2.3', build='1.2.3.29600000').info_plist()
test_eq((built['CFBundleVersion'], built['CFBundleShortVersionString']), ('1.2.3.29600000', '1.2.3'))
built['CFBundleVersion']

info_plist returns the entries for Info.plist, the file macOS reads to learn an app’s name, version and abilities. Three of the defaults matter for a web app in a window. NSAllowsLocalNetworking lets the window load pages from the local server over plain HTTP. NSRequiresAquaSystemAppearance set to False lets the app follow dark mode. LSEnvironment sets PYTHONUTF8 and LANG so that Python starts in UTF-8. Any entry in App.plist overrides the default of the same name.

doc_types

def doc_types(
    extensions, view_elsewhere:tuple=('.svg', '.html', '.htm', '.pdf')
):

Build the Info.plist document types that let Finder open folders, and files with these extensions, in the app.

An app can tell macOS which files it opens, so that Finder lists it under Open With and lets the user drop files on its icon. These declarations go in Info.plist under CFBundleDocumentTypes. doc_types writes two of them. The first covers folders, with the rank Alternate, so the app is offered for a folder without replacing Finder as the default. The second makes the app the Owner, the default editor, of every extension you pass. Extensions a browser shows better, by default .svg, .html, .htm and .pdf, are left out, and the leading dot is optional. Pass the result as App(doc_types=...).

folder, files = doc_types(['.py', 'py', '.rs', '.svg', '.pdf'])
files['CFBundleTypeExtensions'], folder['LSHandlerRank'], files['LSHandlerRank']
(['py', 'rs'], 'Alternate', 'Owner')
test_eq(files['CFBundleTypeExtensions'], ['py', 'rs'])
test_eq(folder['LSItemContentTypes'], ['public.folder'])
