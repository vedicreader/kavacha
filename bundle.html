bundle

Repair a bundle after the freezer has written it: graft packages, shrink it, mend its libraries, install the icon and sign it

A freezer’s output does not always run as it is, and it is often larger than it needs to be. This module fixes a bundle after the freezer has written it. Most of the work is for macOS, where py2app leaves more to fix. finish, near the end of the page, runs the repairs in order and is the function most callers need. The steps are also available one by one, so each can be run and tested on its own. sign comes last, after finish.

graft

def graft(
    app, name, python:NoneType=None
):

Copy the installed package name into a built bundle, replacing the freezer’s copy, and return where it went.

py2app puts pure Python modules into a zip archive inside the bundle, pythonXY.zip, and Python imports them from there. Some packages do not work from a zip: they read their own files from disk, or they carry native programs and libraries that must exist as real files. Copying such a package into the bundle after the freezer has run is called grafting.

graft copies the installed package name from the environment kavacha runs in into the bundle’s lib/pythonX.Y folder, deletes whatever the freezer left in its place, and returns where it put the package, relative to the bundle. It stops with an error if the package is not installed or if the bundle was built for a different Python version than python, which defaults to the running one.

It also compiles the copied files to bytecode in unchecked-hash mode. Python loads such .pyc files without comparing them to the source. A signed bundle is read-only, and without these files Python would try to write bytecode into it the first time the package is imported.

app, lib = mkapp('Demo.app')
(lib/'json.cpython-311-x86_64-linux-gnu.so').write_text('what the freezer flattened')
graft(app, 'json')
Path('Contents/Resources/lib/python3.11/json')

graft finds the lib/pythonX.Y folder in either layout: under Contents/Resources/lib in a macOS app, or under lib in a Windows build.

(root/'Win'/'lib'/ver).mkdir(parents=True)
_lib_dir(root/'Win').relative_to(root)
Path('Win/lib/python3.11')

link_duplicates

def link_duplicates(
    app, names, floor:int=1000000
):

Hardlink identical files of at least floor bytes across the packages in names, and return the megabytes saved.

Some packages ship identical large files. playwright and patchright, for example, each carry the same Node.js executable. link_duplicates looks through the packages in names, finds files of at least floor bytes (1 MB by default) with the same content, and replaces each later copy with a hardlink to the first, so the data is stored once. It returns the megabytes saved. finish runs it over the grafted packages.

app2, lib2 = mkapp('Link.app')
node = os.urandom(2_000_000)                          
for n in ('playwright', 'patchright'):
    (lib2/n).mkdir(); (lib2/n/'node').write_bytes(node)
link_duplicates(app2, ['playwright', 'patchright'])
2

strip_zip

def strip_zip(
    app, prefixes:tuple=()
):

Delete the entries that start with any of prefixes from the bundle’s zip archive, and return the megabytes saved.

Once a package is grafted, the freezer’s copy of it in the zip archive is never imported, but it still takes up space. So does code nothing reaches, such as the standard library’s tests. strip_zip deletes every archive entry whose path starts with one of prefixes, keeps the rest unchanged, and returns the megabytes saved. A prefix is matched as plain text, so end it with / to remove a single package. The example removes json/ and keeps jsonschema; the prefix json would have removed both.

app4, lib4 = mkapp('Zip.app')
z = lib4.parent/zipname
with zipfile.ZipFile(z, 'w', zipfile.ZIP_DEFLATED) as f:
    f.writestr('json/decoder.py', os.urandom(3_000_000))
    f.writestr('jsonschema/_types.py', 'another package that starts with json')
    f.writestr('kavacha/window.py', 'the app itself')
strip_zip(app4, ('json/',))
3
with zipfile.ZipFile(z) as f: kept = f.namelist()
kept
['jsonschema/_types.py', 'kavacha/window.py']

install_modern_icon

def install_modern_icon(
    app, icon, identity:NoneType=None, deployment_target:str='14.0'
):

Install an Icon Composer .icon into the bundle before signing, keeping the .icns icon as the fallback.

macOS 26 introduced a new kind of app icon, made with Apple’s Icon Composer and saved as a .icon folder. install_modern_icon adds such an icon to a built bundle with the iconmage tool and keeps the .icns icon for older systems. It changes the bundle, so it must run before signing. When icon is empty or not a folder it does nothing. When iconmage is not installed, or the install fails, it prints why, leaves the .icns icon in place and returns None. The example runs on a machine without iconmage.

(root/'Demo.icon').mkdir()
install_modern_icon(app, root/'Demo.icon') is None
  iconmage not installed; keeping the ICNS icon alone (uv tool install git+https://github.com/AnswerDotAI/iconmage.git)
True

is_macho

def is_macho(
    p
):

Whether p starts with a Mach-O or universal header.

Compiled programs and libraries on macOS are Mach-O files. A Mach-O file begins with load commands, a header that lists its segments, its code signature, its install name (the path other programs use to find it), its version, a UUID and the libraries it depends on. A universal file holds one Mach-O slice per CPU architecture.

is_macho checks whether a file starts with a Mach-O header. macho reads the header of each slice and returns those facts as a list of dicts, or None for a file that is not Mach-O. corrupt reports a file whose header does not describe its body, for example one whose last segment does not end where the file does. codesign refuses to sign such a file and reports “main executable failed strict validation”. The example reads the system’s own /usr/lib/dyld when it exists, which is the case on a Mac.

l = Path('/usr/lib/dyld')
is_macho(l) and [(s['type'], s['seg_end'] == s['size']) for s in macho(l)], corrupt(l)

mend_frameworks

def mend_frameworks(
    app, search:tuple=()
):

Replace each corrupt library in Contents/Frameworks with a healthy installed copy, and report file names with more than one build installed.

py2app copies the native libraries a bundle needs into Contents/Frameworks and names each copy by its file name alone. When two different libraries share a file name, for example two builds of the same library shipped by two packages, the copies get mixed up: one file ends up with the body of one library and the header of the other, which makes it corrupt in the sense above.

mend_frameworks finds each corrupt file in Contents/Frameworks and replaces it with a healthy installed copy. It looks among the libraries the interpreter and the bundled packages link to, plus any folders in search, and prefers a copy the same size as the corrupt file, then the highest version. It then points the copy’s install name and dependencies at Contents/Frameworks and signs it ad hoc.

It returns two dicts. mended maps each repaired file name to the copy used, or to None when no healthy copy was found. clashes lists every file name that has more than one distinct build installed on this machine, whether or not it caused a problem this time. The example bundle has no Frameworks folder, so both are empty.

app6, _ = mkapp('Mend.app')
mend_frameworks(app6)

sign

def sign(
    app, identity, entitlements:NoneType=None, run:NoneType=None
):

Code-sign every Mach-O file deepest first, then each framework, then the bundle, signing hardlinked files once and never using --deep.

macOS only runs a downloaded app if it is signed, and the signature has to cover every program and library inside it. sign signs the bundle with identity, the name of your signing certificate, or - for an ad hoc signature that only works on your own machine. It signs each Mach-O file first, deepest in the folder tree first, then each .framework, then the bundle, and finally verifies the result. It does not use codesign --deep, which would sign everything with the same options. Every file is signed with the hardened runtime (--options runtime), which Apple’s notarisation requires.

Executables get the entitlements file, as the bundle does. Libraries ending in .so or .dylib do not. Files that are hardlinks of one another are signed once: codesign --force writes a new file, which breaks the link, so sign links the other paths back to the signed file.

run is the function that runs each command. The example passes one that records the commands instead of running them, so it needs no certificate.

app7 = root/'Sign.app'
for rel in ('Contents/MacOS/Sign', 'Contents/Resources/lib/a/node', 'Contents/Resources/lib/x.so'):
    (p := app7/rel).parent.mkdir(parents=True, exist_ok=True); p.write_bytes(b'\xcf\xfa\xed\xfe' + bytes(28))
(app7/'Contents/Resources/lib/a/node').chmod(0o755)
os.link(app7/'Contents/Resources/lib/a/node', app7/'Contents/Resources/lib/b')
calls = []
sign(app7, 'ID', 'ent.plist', run=lambda *a: calls.append([str(x) for x in a]))
[c[-1].replace(str(root), '') for c in calls]

finish

def finish(
    app, spec, identity:NoneType=None
):

Run every repair a frozen bundle needs, in order, and return what each step did.

finish runs the repairs above in the order they depend on each other. It grafts each package in spec.grafted, deletes their copies and the spec.unreachable prefixes from the zip archive, hardlinks duplicate files in the grafted packages, repairs Contents/Frameworks, and installs spec.modern_icon if there is one. It returns a dict with the result of each step, which build prints. It does not sign the bundle, so call sign afterwards.

app5, lib5 = mkapp('Fin.app')
with zipfile.ZipFile(lib5.parent/zipname, 'w', zipfile.ZIP_DEFLATED) as f:
    f.writestr('json/decoder.py', os.urandom(2_000_000))
    f.writestr('test/test_json.py', os.urandom(1_000_000))
    f.writestr('kavacha/window.py', 'the app itself')
finish(app5, App('Demo', 'app.py', grafted=['json'], unreachable=['test/']))
{'json': 'Contents/Resources/lib/python3.11/json',
 'stripped_mb': 3,
 'linked_mb': 0,
 'modern_icon': False}

The grafted json package is now a folder in lib, and the archive keeps neither its old copy nor the test/ entries marked as unreachable.

with zipfile.ZipFile(lib5.parent/zipname) as f: left = f.namelist()
left, (lib5/'json'/'decoder.py').exists()
(['kavacha/window.py'], True)

frozen_distribution

def frozen_distribution():

Return a setuptools Distribution class that ignores the dependencies the project declares.

py2app runs from a setup.py, through setuptools. setuptools also reads the project’s pyproject.toml, so the dependencies listed there become requirements of the freeze, alongside what the App says. frozen_distribution returns a setuptools Distribution class that empties install_requires after the configuration has been read, so the App is the only description of what goes into the bundle. Pass it to setup as distclass.

d = frozen_distribution()({'name': 'demo', 'install_requires': ['fastcore']})
d.parse_config_files()
d.install_requires
